## 1. 从玩法出发

先确定玩家反复执行的核心动作，再让剧情赋予动作意义。例如“重复探索”可对应修复记忆，“管理资源”可对应在两群人之间分配生存权。避免剧情赞美仁慈，而核心玩法只奖励无差别掠夺，除非这种矛盾正是主题。

定义玩家身份的三层内容：系统允许做什么、世界认为玩家是谁、玩家逐渐发现自己是谁。三层之间的张力可持续制造剧情。

## 2. 任务结构

一个可用任务包含：

`触发条件 → 表面目标 → 行动阻力 → 新信息 → 目标重释 → 玩家选择/关键操作 → 世界反馈 → 后续状态`

支线应至少改变一项：玩家对主线的理解、一个关键关系、可用资源/路径、结局判断。纯填充任务应合并或删除。

让任务目标可操作，剧情目标可感受。例如系统目标是“取回三枚徽章”，人物目标是“决定是否证明父亲是叛徒”。

## 3. 选择与分支

好选择让玩家表达价值观，并承担可理解但不完全可预测的后果。至少改变以下一项：

- 资源：获得一项就失去另一项。
- 关系：角色信任、恐惧、依赖或离开。
- 信息：不同路线知道不同真相。
- 身份：阵营、名声、职业或自我理解。
- 世界：地点、规则、存亡或权力结构改变。

使用“辫状分支”控制规模：短期分开体验，中期汇回共享节点，但保留状态差异并在后续反馈。只有主题核心选择才扩展为长期独立路线。

不要把选项写成明显的善/恶按钮。让每个选项保护一种正当价值，同时伤害另一种价值。提前说明角色能合理预见的风险；不要用完全无从判断的惩罚冒充深度。

## 4. 对话节点

每个对话节点明确说话者目标、策略和不能直说的内容。选项应代表不同意图，而不只是同一句话的三种语气。

推荐标注：

```
[节点 ID / 触发条件]
场景动作或镜头
角色：对白
玩家选择：
A. 意图或台词 → 状态变化 → 跳转节点
B. 意图或台词 → 状态变化 → 跳转节点
```

给重要 NPC 独立词汇、句长、回避方式和情绪防线。信息型对白也应包含谈判、试探、遮掩或关系变化。

## 5. 状态与结局

只追踪会在文本、玩法或结局中产生可见反馈的状态。为每个状态写清：取值范围、何时改变、何处反馈、是否影响结局。

结局不是累计分数后的标签，而是玩家长期选择所代表价值观的最终压力测试。隐藏结局必须有可追溯条件；不要要求与主题无关的收集劳动。

共享结局场景可根据状态替换角色、对白、环境和代价，使收束可控又能承认玩家经历。

## 6. 可实现性检查

- 每个分支是否有唯一体验或后续反馈？
- 选择前是否有足够信息形成判断？
- 状态变量是否实际被读取？
- 分支数量是否与制作规模匹配？
- 关键情报是否存在至少一条不可错过的获取路径？
- 玩家失败是否产生新局面，而不只是重复读取存档？
- 剧情目标与玩家操作是否一致？
- 结局是否回收玩家最重要的选择和核心关系？
